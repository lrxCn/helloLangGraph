# 短期/中期/长期记忆分层改造实现 Prompt（给其他 AI）

你是一个资深 Python Agent 工程师。请在**现有项目代码**上直接实现“短期记忆 + 中期总结 + mem0 长期记忆协同”方案，禁止只给建议不落地。

## 前置背景（必须遵守）

1. **项目框架**：使用 `langgraph` 和 `create_agent` 构建。
2. **环境管理**：本地安装了 `uv`，所有依赖管理优先使用 `uv` 命令。
3. **配置系统**：已有 `src.config.settings` 统一管理环境变量。
4. **向量数据库**：已在本地运行 Qdrant（地址：`localhost:6333`）。

## 目标

在不破坏现有功能的前提下，实现以下能力：

1. 建立**短期记忆**（线程内会话记忆）：用于当前 `thread_id` 的上下文保留与恢复。
2. 建立**中期总结**（滚动摘要）：周期性压缩近期会话，降低上下文膨胀。
3. 保持 **mem0 作为长期记忆**：只保存长期有效信息，避免每轮对话都写入 mem0 造成噪声。
4. 明确三层记忆边界与数据流：短期/中期/长期各司其职。

## 关键设计约束（必须满足）

1. **禁止**继续“每轮都把用户+助手整段写入 mem0”。
2. 长期记忆写入必须有**准入策略**（规则或轻量分类），仅写入长期稳定事实，例如：
   - 用户偏好（语言风格、输出偏好等）
   - 稳定身份信息
   - 长期项目约束/目标
3. 中期总结应为线程级，并可在同一线程后续轮次被注入使用。
4. 设计要兼容当前项目结构，优先在现有文件中演进，不要大规模重构。
5. 代码与注释使用简体中文或清晰英文均可，但风格要统一、可维护。

## 你需要完成的实现项

### A. 状态结构扩展（短期 + 中期）

在 `langgraph`/agent 状态中新增并使用以下字段（命名可微调，但语义必须保留）：

- `running_summary`: `str`，滚动中期摘要
- `turn_count`: `int`，当前线程轮次数
- `last_summary_turn`: `int`，上次总结时的轮次

要求：

- 每轮结束后更新 `turn_count`。
- 当满足触发条件时生成/更新 `running_summary`。

### B. 中期总结触发器

实现一个明确的触发策略（可配置）：

- 默认每 `N` 轮触发一次（建议默认 `N=8`，并放到 `settings` 可配）
- 支持后续扩展为 token 阈值触发（本次可先留接口/注释）

### C. 中期总结生成逻辑

实现一个“摘要合并”逻辑，输入为：

- 旧 `running_summary`
- 最近若干轮关键对话（至少包含最新用户输入、助手输出）

输出为新的 `running_summary`，要求：

- 保留任务目标、关键约束、已完成事项、待办事项
- 删除寒暄/噪声
- 长度受控（例如 150~300 中文字，可配置或常量）

### D. Prompt 注入策略（before_model）

在模型调用前，注入记忆信息时按优先级组织：

1. 短期关键上下文（最近几轮，必要时）
2. `running_summary`（若存在）
3. mem0 检索结果（长期记忆）

要求：

- 明确区分“会话内记忆”和“长期记忆”，避免混淆。
- 注入内容要可控，不要无限增长。

### E. mem0 长期记忆写入准入（after_agent）

新增一个函数（或模块）用于判断“本轮是否值得写入 mem0”，例如：

- `should_archive_to_long_term(user_input: str, assistant_output: str) -> bool`
- `extract_long_term_facts(...) -> list[str]`

规则至少覆盖：

- 命中长期偏好/稳定事实时写入
- 一次性问答、临时任务中间态不写入

### F. 配置项补充（settings）

在 `src.config.settings` 增加必要配置（含默认值）：

- `SHORT_TERM_SUMMARY_INTERVAL`（默认 8）
- `SHORT_TERM_RECENT_TURNS`（默认 4）
- `SHORT_TERM_SUMMARY_MAX_CHARS`（默认 300）
- 如需其他配置可补充，但必须有合理默认值

### G. 测试与验证（至少完成最小可运行验证）

至少给出并执行以下验证（可用脚本或测试）：

1. 同一 `thread_id` 下多轮对话，`running_summary` 会按间隔更新
2. 非长期信息不写入 mem0
3. 长期偏好信息会写入 mem0 且能在后续检索到
4. 记忆注入的 system prompt 中同时体现中期摘要与 mem0 检索结果
